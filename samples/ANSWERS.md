# 실습 정답지 (먼저 보지 말고, 직접 로그를 읽어본 뒤 확인하세요)

각 리포트를 아래 기준으로 채점합니다. 항목당 1점, 케이스당 만점 4점.

## case1_repo_full.log — 리포지토리 용량 부족
1. 직접 원인: 리포지토리 디스크 공간 부족 (Win32 error 112)
2. 숨은 원인: Hard disk 2의 **CBT가 깨져서 전체 스캔(1.6TB 읽기)**이 일어났고, 증분인데 418GB가 전송됨
3. 시작 시점부터 여유 공간이 5%뿐이었다는 경고를 연결해서 설명
4. 조치: 공간 확보(보존 정책·오래된 체인 정리) + **CBT 재설정**(VM의 CBT 리셋) 둘 다 제시

## case2_credentials.log — 게스트 자격 증명 실패
1. 결과가 **Failed가 아니라 Warning**임을 정확히 구분 (백업 자체는 crash-consistent로 성공)
2. 원인: 서비스 계정 `svc_veeam`의 **비밀번호 변경/만료 또는 계정 잠김**
3. 여러 VM에서 같은 계정으로 동시에 실패 → 개별 VM 문제가 아니라 계정 문제라는 판단
4. 조치: AD에서 계정 상태 확인 → Veeam 자격 증명 관리자에서 비밀번호 갱신 → "Test Now"로 확인. **애플리케이션 일관성(SQL 등)이 빠진 상태**라는 위험도 언급

## case3_snapshot.log — 스냅샷 생성 실패
1. 직접 원인: 스냅샷 생성 타임아웃
2. **41일 된 Veeam 임시 스냅샷이 남아 있음**(이전 작업이 정리 못 한 고아 스냅샷)을 짚음
3. **데이터스토어 여유 공간 3.1%**를 연결해서 설명 (스냅샷 델타 파일 공간 부족 위험)
4. 조치: vSphere에서 스냅샷 통합(Consolidate)·삭제, 데이터스토어 공간 확보 후 재시도. **운영 DB VM이라 업무 시간 외 작업** 같은 주의사항 언급
